# Personal Pages

个人主页，使用 Vue 3、Express、SQLite 和 Docker。页面包括 Index、Moments、Resource 和 Activities；内容在 `/admin` 管理。

Logo 右侧的月亮 / 太阳按钮可以切换全站浅色、暗色模式，包括后台和图集预览。默认浅色，选择保存在当前浏览器；再次访问时在页面绘制前恢复。支持 View Transitions 的浏览器会从按钮中心向外展开圆形过渡；旧浏览器或启用减少动态效果时直接切换。

圆形过渡持续 900ms，使用圆形容器缩放与画面反向缩放；动画关键帧只生成一次，圆心与半径在按钮位置、窗口尺寸不变时复用，悬停或键盘聚焦时提前准备。每次切换仍使用当前页面的浏览器快照，避免缓存旧的文章、后台输入或弹窗内容。

## 唱片首页与音乐

首页先显示固定深棕色的开始界面，唱片位于上方，下面三行欢迎文字依次出现，最后显示“进入网站”按钮。欢迎文字在 `/admin` 的 **首页介绍 → 开始界面** 编辑，随“保存首页”一起保存。点击唱片或进入按钮会启动同一首音乐并展开首页；文案淡出，背景从唱片中心扩散为当前亮色 / 暗色模式的正常背景。扩散复用主题切换的 900ms 动画曲线与预生成关键帧，唱片位移和旋转保持独立；启用减少动态效果时直接展开。

电脑端采用播放器与内容 2:3 布局，手机端上方三分之一常驻播放器；下方通过上下按钮循环浏览关于我、最新四条动态和最新四项根资源。内容随实际高度展开，统一滚动网页，不再在右侧卡片区域内滚动；下方切换按钮随内容放置。站主名称、描述与介绍卡片仍从后台读取。

开始界面还提供“静音访问”：正常开始播放，但在播放前将音量设为 0，唱片继续旋转。在播放器里点击音量图标，可展开 0–100% 滑条并静音 / 恢复先前音量；图标分别显示静音、低、中、高四种状态。音量与播放进度一样在站内切页时保留；支持 Web Audio 时通过同一增益节点调整，保持流式播放和已有缓存机制。

在 `/admin` 的 **首页介绍 → 首页歌单** 批量上传 MP3，编辑歌曲名称、作者和顺序，然后保存首页。未配置歌单时可以展开首页内容，但音乐控件禁用；首次点击播放会从第一首开始。歌单支持上一首、播放 / 暂停、下一首、选曲，以及单曲循环（默认）、列表循环、随机播放。

音乐由全站共享的播放器播放，站内切页不会中断；离开首页时唱片移入 Logo 左侧，点击小唱片可暂停或继续，返回首页时恢复大唱片。直接访问或刷新其他页面也会显示 Logo 左侧的小唱片，返回首页直接展开内容，不再显示开始界面。直接打开首页时仍显示开始界面；刷新后的音乐需要再次主动点击播放。

HTTPS 或 localhost 环境使用 Service Worker 缓存完整 MP3：首次下载同时流式播放，下载完成后循环、切回歌曲和拖动进度使用本地缓存。单曲循环只请求当前歌曲，列表 / 随机模式在最后 30 秒预取下一首。歌单删除的歌曲会清理浏览器缓存；缓存被浏览器清除、空间不足或不支持 Service Worker 时会使用正常网络播放。上传文件的服务器引用保护也包含已保存歌单。

无需新增 `.env` 配置。升级后重启后端以创建歌单表，并重新构建前端；Docker 部署运行 `docker compose up -d --build`，包含音乐文件缓存响应与 Service Worker 更新配置。

## 部署

1. 复制 `.env.example` 为 `.env`，设置强密码 `ADMIN_PASSWORD` 和随机 `SESSION_SECRET`。这两个变量仅供服务端使用，不会写入前端构建产物。旧版的 `VITE_ADMIN_PASSWORD` 已不再使用。
2. 运行 `docker compose up -d --build`。
3. 访问 `http://localhost` 或已配置证书的站点，打开 `/admin` 登录。

数据库保存在 `server/data`，上传内容保存在 `public/picture` 和 `public/source`。上线前请备份这两个目录。首次启动会从旧首页配置导入头像、名称、描述和卡片；旧教程与项目卡片会分别导入动态和资源库，关联的 Markdown 文件会写入新正文。标注“施工中”的内容会导入为草稿。旧数据库表不会被删除。

## 本地开发

前端：在仓库根目录运行 `npm install`、`npm run dev`。Vite 将 `/api` 代理到 `http://localhost:3002`。

后端：使用 Node 22.19+ 或 Node 24+（推荐），在 `server` 目录运行 `npm install`，然后执行 `npm start`。服务会自动读取仓库根目录的 `.env`；其中可设置 `ADMIN_PASSWORD`、`SESSION_SECRET`、`SERVER_PORT` 和 `DEEPSEEK_API_KEY`，端口默认是 3002。已在系统环境变量中设置的同名值优先。后端使用 Node 自带的 `node:sqlite`，原有 SQLite 数据文件可继续使用。

```powershell
npm start
```

## 访客账号

导航栏最右侧提供“登录/注册”入口，登录后显示用户名，点击进入 `/account` 查看自己的注册资料并退出登录。访客账号与 `/admin` 管理员会话使用不同 Cookie，互不授权。登录支持用户名或邮箱；不存在的账号会提示“此用户尚未注册”。注册完成后自动登录，并返回进入登录页前的页面。

在**仓库根目录 `.env`** 增加：

```dotenv
QQ_SMTP_USER=你的QQ号码@qq.com
QQ_SMTP_AUTH_CODE=你生成的16位QQ邮箱授权码
```

发件邮箱必须是站长自己的 QQ 邮箱。登录 QQ 邮箱，进入“设置 → 账号与安全 → 安全设置”，开启 POP3/IMAP/SMTP 服务并生成授权码。这里填写的是**授权码，不是 QQ 登录密码**，详见 [QQ 邮箱官方说明](https://help.mail.qq.com/detail/106/985)。服务器固定使用 `smtp.qq.com:465` 和 TLS；无需额外填写 SMTP 主机或端口。站点名称从后台的首页资料读取，用于邮件主题和发件人名称。邮件使用亮色色块与叠层配色，并提供纯文本替代内容，不加载远程跟踪图片。

保持现有 `SESSION_SECRET` 为固定的长随机值；验证码摘要与防滥用计数使用它进行 HMAC。密钥只由后端读取，不要添加 `VITE_` 前缀，也不要提交真实 `.env` 到 Git。配置后重启后端；Docker 部署运行 `docker compose up -d --build`，Compose 已配置转发这两个邮箱变量。

- 注册必须填写用户名、邮箱、站内密码和 6 位邮箱验证码。用户名支持 2–24 个汉字、字母、数字、下划线或连字符；按 Unicode NFKC 规范化，唯一性及登录匹配不区分字母大小写。密码为 8–128 个字符。
- 登录页提供“忘记密码”入口（`/reset-password`）：填写注册邮箱、邮箱验证码、新密码及确认密码，验证成功后重设密码并自动登录，无需旧密码。全部旧登录会话会被撤销；原密码不能再登录。沿用现有 QQ 邮箱配置，无需新增环境变量。
- 验证码在邮件发送成功后两分钟内有效；同一邮箱一分钟内不能重发，刷新或重启服务不能绕过冷却期。注册码与重设密码码绑定不同用途，但共用邮箱冷却及发送额度。新请求立即替换旧码，成功注册或重设后删除验证码；连续错误 5 次后必须获取新码。
- 发送与登录均有服务端限流；单 IP 每 15 分钟最多 10 次验证码请求，同一邮箱每天最多发送 20 次，全站每小时最多发送 100 次。重发等待和发送失败均以服务端状态为准。
- 密码保存为随机盐的 scrypt 哈希，验证码保存为 HMAC 摘要；会话使用随机令牌，数据库只保存令牌的 SHA-256 摘要。用户、验证码、限流状态及 7 天有效的登录会话持久化到 `server/data/card.sqlite`，退出登录会撤销当前会话。
- 访客 Cookie 使用 HttpOnly、SameSite=Strict，在 HTTPS 请求下启用 Secure；写接口校验请求来源及 JSON 类型。访客登录不能访问管理员接口。完整邮箱只在本人账号资料和管理员举报处理接口返回，公开评论仅返回脱敏邮箱。
- 请求日志不记录认证接口的查询参数、密码、验证码或邮件内容；过期会话、验证码和限流记录随接口访问定期清理。防滥用计数记录的是 HMAC 摘要，不保存明文 IP。

注册与登录页面下方说明邮箱用途及隐私设计；注册不会自动订阅访客。订阅由用户主动开启，回复邮件默认开启，可在账号设置中关闭。广场活动在后续迭代中开放。邮箱未配置时仍可登录已有账号，验证码发送入口会提示暂未开放。

`server/test/auth.test.js` 使用隔离内存数据库、可控时间和模拟邮件覆盖注册/登录、冷却与过期边界、重发替换、并发注册、邮件失败及会话撤销；不向 QQ 邮箱建立连接或发送真实邮件。

## 新内容订阅

在根目录 `.env` 增加网站的**公开根地址**，邮件链接会使用这个地址，不根据请求中的 Host 拼接：

```dotenv
# 部署
PUBLIC_SITE_URL=https://quininezzzz.top
# 本地开发时替换为实际前端端口，例如 http://localhost:5174 或 http://localhost:5188
```

沿用 `QQ_SMTP_USER`、`QQ_SMTP_AUTH_CODE`，无需新的邮箱授权。后端自动读取根目录 `.env`；修改后重启后端。Docker 部署需运行 `docker compose up -d --build`，Compose 会转发 `PUBLIC_SITE_URL`。只接受 HTTP(S) 根地址，不能包含账号密码、路径、查询参数或锚点；生产环境未配置有效地址时暂停订阅邮件发送。

- **资源库**：大标题下方提供“全部订阅”和“按类订阅”；后者展开多选浮窗，从后端提供的大类中勾选，点击“保存选择”统一更新。合集卡片和合集页面各有订阅按钮，普通文档及图集不提供单项订阅。合集的通知包含其全部嵌套子合集中的新增资源。
- **递归管理**：大类订阅依据根资源、根合集的大类，递归覆盖其全部子合集及草稿成员。之后新增子合集自动继承上级订阅状态；将子合集移至另一个根合集后，按新根大类判断通知对象。单独订阅或取消某个合集是该分支的独立选择；再次订阅或取消整个大类，会深度遍历并重置该类下全部合集的选择。全库取消会清除全部资源订阅，不影响动态订阅。
- **动态**：大标题下方同样提供“全部订阅”和“按类订阅”，浮窗中可多选短帖、长文；浏览 Tab 不影响订阅选择。全部订阅覆盖两种形式，单独取消某种形式后另一种继续生效；全部取消会清除两种订阅。
- **发布规则**：只通知首次公开发布，包括草稿首次发布及 AI 新学习报告。编辑、改变分类、移动已公开资源、修改发布时间、撤回后重新公开不会重新通知。上级合集是草稿时不会通知；上级首次公开时，首次公开的子内容才进入队列。功能首次安装不会补发现有公开内容。
- **邮件与降频**：邮件采用网站的亮色色块叠层样式，包含标题、摘要、新内容网页链接及管理订阅链接。短帖链接直接在动态列表显示对应帖子，无需详情页。同一邮箱的动态、资源及重叠订阅共用 30 分钟冷却，期间的其他提醒直接跳过，不延迟补发；验证码邮件不受此订阅冷却限制。
- **队列与取消**：订阅、发布事件、邮件队列及邮箱冷却时间保存在 SQLite；重启后继续处理。邮件发送失败最多尝试 3 次；超时等无法确认投递结果的情况保留冷却后才重试。发送前再次检查是否仍订阅、是否仍公开；取消后尚未发送的提醒跳过。删除分类或合集会递归清理对应订阅，删除内容会清除它的待发事件。已交给邮件服务器发送的邮件无法撤回。
- **游客提示**：未登录点击订阅，显示网站自绘提示卡片“登录/注册后即可使用订阅服务”，2 秒后淡出；已登录的订阅按钮会变为“取消订阅”。

`server/test/subscriptions.test.js` 使用模拟邮件覆盖递归订阅、删除清理、首次发布、草稿公开、重叠去重、跨队列重启的冷却、失败重试、取消及访客权限；不会发送真实邮件。

## 阅读与评论

长文、普通资源文档及图集在电脑端使用 **1:3 双列布局**：左上为 Markdown 标题目录，滚动时突出当前章节，并自动将当前章节移到目录可视范围中央，点击可跳转。目录可以独立手动滚动；再次滚动正文时，即使仍在同一章节，也会自动回到阅读位置。左下为评论区，右侧保留阅读内容。手机端通过左侧“目录 / 评论”按钮展开滑动侧栏，占屏幕宽度的三分之二。短帖的评论区直接显示在动态列表中的对应短帖下方，无需详情页；合集暂不提供评论。

- 登录后可发布纯文本评论或回复（最多 2000 个 Unicode 字符）。用户名深色显示，邮箱以 `o***@example.com` 形式浅色显示，完整地址不会公开。评论默认按点赞数排序，同赞数时较新在前，可切换“最新优先”；每人对每条评论只能点一个赞，可再次点击取消。
- 评论和回复正文超过三行时默认折叠，可“展开 / 收回”。点赞使用空心 / 实心爱心图标，回复使用聊天图标；点击三个点打开更多操作，提供复制、举报和仅本人可见的撤回。复制会写入系统剪贴板，包含折叠的完整正文。
- 回复任何层级的消息都归入同一根评论的回复区，显示“回复 @用户名：”，只缩进一层、按时间先后排序。默认显示三条，可展开或收起。邮件链接可定位到被回复的内容；回复较多时分批读取。
- 作者可撤回自己的发言。撤回根评论同时清除全部回复、相关点赞和待发回复邮件；撤回一条回复只清除该条内容，其他回复保留原来的 @ 用户名。
- 举报弹窗支持多选“广告营销”“色情低俗”“引战暴力”“政治敏感”“侵犯权益”和带说明的“其他描述”。举报进入后台 **举报内容处理**，可删除、删除并封禁邮箱、保留、保留并不再提醒。对同一条内容的待处理举报一并处理；删除后仍保存内容和举报快照。每个账号对同一条内容的重复举报不再生成记录；标记不再提醒后，后续举报正常显示成功，但不保存、不发邮件。
- 后台 **黑名单用户** 支持手动添加和解除邮箱封禁。封禁立即撤销该邮箱的访客会话，禁止注册、登录、验证码找回和评论，也停止该邮箱尚未发出的订阅及回复邮件；解除后需要重新登录。其他历史发言保留。
- 回复提醒默认通过现有 QQ 邮箱发送给实际被 @ 的用户，自己回复自己不发邮件。用户在 **个人账号 → 账号设置 → 接收回复提醒邮件** 中可随时关闭；发送前重新检查该设置。邮件包含内容链接和关闭提醒的操作说明。
- 举报通知由配置的 QQ 邮箱发给同一邮箱，所有举报共用持久化的 30 分钟冷却，期间其他举报仍进入后台，但通知邮件跳过，不补发。举报冷却独立于订阅及验证码邮件；已处理、已撤回或静默的内容不再发待发举报通知。邮件失败保留队列并有限重试。

无需新增 `.env` 项：沿用 `QQ_SMTP_USER`、`QQ_SMTP_AUTH_CODE` 和 `PUBLIC_SITE_URL`。重启后端时自动在现有 `card.sqlite` 中创建评论、点赞、举报、黑名单及邮件队列表，并为既有账号增加默认开启的回复通知设置。

`server/test/comments.test.js` 使用内存数据库、模拟时钟、模拟邮件覆盖权限、点赞排序、扁平回复、撤回级联、举报静默、封禁、偏好设置与通知冷却，不发送真实邮件。评论接口对写操作校验来源、JSON 和访客会话，并按账号限制发言、点赞和举报频率；评论中的 HTML 当作普通文字显示。

## 内容管理

- **首页介绍**：上传头像，编辑名称、描述以及任意数量的 Markdown 卡片。卡片支持链接、代码块、加粗、斜体、删除线；下划线使用 `++文字++` 或 `<u>文字</u>`。
- **动态**：通过“全部 / 短帖 / 长文”切换浏览，搜索、排序和分页会按所选形式过滤。创建长文或无标题短帖，编辑摘要、正文、标签、发布时间和草稿状态。短帖正文最多 500 字（包含 Markdown 标记和链接地址，按 Unicode 字符计数，忽略首尾空白），以 18px 字号直接显示在列表中，默认显示 5 行，超出时可展开或收回；短帖没有详情页。
- **资源库**：支持文档、合集和图集三种形态，均可设置标签、封面和链接按钮。只有根资源、根合集可选择大类，大类仅用于资源库根界面的筛选和订阅；合集内部不显示大类导航和分类标记，搜索当前合集时也不按大类过滤。文档使用 Markdown 正文；图集支持批量上传、图片说明、调整顺序，以及瀑布流和大图预览。
- **合集**：每项资源可选择一个所属合集，合集也可嵌套到其他合集中。其内部成员的大类自动继承父合集，不可单独编辑；修改根合集大类或移动整个子树时，文档、图集、嵌套合集及草稿全部同步。在合集编辑器里勾选已有资源即可移入；取消勾选的原成员回到资源库首页，并保留最后继承的大类，之后可在根层级单独修改。归入合集的内容只在相应合集内列出，面包屑可返回各级合集。上级合集为草稿时，下级内容也不公开；删除合集会将直接成员移回资源库首页。
- **搜索与排序**：标题、标签和正文同时匹配。平时可选择“最新发布 / 最新修改”，默认最新发布；进入搜索时默认按匹配程度排序，也可选择这两种时间排序。合集的最新修改时间包含子内容的更新。
- **活动**：预留“施工中”页面。
- **站点文案**：动态、资源库、活动页的说明文字和页脚备案号可在后台修改。

后台的资源分类管理整合在“资源库”列表上方的折叠面板内。动态、资源库管理支持按标题、标签、摘要、正文和图片说明搜索，以及“最新修改 / 最新创建”排序。资源树按根项目分页，每页最多 15 项；子成员不占根项目名额，每层兄弟内容沿用当前排序。每个合集默认显示 3 个直接成员，可展开、收起；搜索时保留匹配内容的祖先并自动显示匹配分支。切换排序或搜索时回到第一页，翻页保留排序。

子内容新增、编辑、移入、移出或删除时，会更新全部上级合集的最新修改时间，创建时间保持不变。后端首次升级自动根据现有成员的修改时间回填合集时间，后续后台保存和 AI 发布由数据库规则同步。前台动态、资源库及合集内部列表每页最多 15 项，与后台共用数字分页按钮；短帖邮件链接会打开该短帖所在的页码。

上传文件最大 200 MB。图片在 `/picture`，其他文件在 `/source`；HTML、SVG、JavaScript 等可执行网页文件禁止上传。

图集详情页的“图集”标题旁提供“下载整个图包”。本地图片及公网外链图片按图集顺序编号，保留原文件字节并打包为 ZIP，重名图片不会覆盖。打包过程中显示等待状态，任何图片读取失败都提示错误，不提供缺图的压缩包；空图集禁用按钮。单个图包最多 2 GB，单张外链图片最多 50 MB。图包生成在系统临时目录，由浏览器直接下载，不占用上传引用目录；下载完成或失败后删除，未下载的图包 5 分钟后清理。草稿图集及草稿合集内的图集不可下载。

资源库搜索针对当前层级的内容，图集的图片说明也参与匹配。保存时会检查本地文件引用，并清理没有被任何已保存内容引用的后台上传文件；图集图片（包括草稿图集）、头像、封面、正文和按钮链接都会参与引用保护。

重启后端时自动统一旧内容的分类，以所属根合集为准，保留根层级已有的大类。旧订阅中与上级默认相同且同次写入的重复合集记录会整理为继承状态，独立选择及取消记录保留。SQLite 触发器保证后台、AI 报告及后续移动均遵守分类继承；分类变更不会触发已有内容更新通知。`server/test/resource-categories.test.js` 覆盖迁移、递归继承、移动、删除及订阅边界。

## 访客反馈

首页音乐播放器左下角提供“向我反馈”入口。游客点击会显示登录提示；登录后在网站弹窗单选“体验优化 / bug反馈 / 音乐推荐 / 侵权通知 / 其他内容”。音乐推荐填写歌名、歌手名和可选备注；其他类型填写反馈内容，可添加最多 4 张 PNG、JPEG、GIF、WebP 图片，每张不超过 5 MB、合计不超过 10 MB。图片与表单一起提交，不会因取消弹窗产生服务器上的临时上传。

每位用户在任意连续 30 分钟内最多成功提交 3 次反馈，限制在数据库中持久保存，重启与审批均不会重置计数。反馈保存后加入独立邮件队列，使用已有的 `QQ_SMTP_USER` 和 `QQ_SMTP_AUTH_CODE` 自己给自己发邮件，包含账号名、账户邮箱、反馈全文及所有辅助图片；音乐推荐包含全部歌曲字段。邮件支持直接回复账户邮箱。每条反馈都通知，不与订阅、举报邮件共用冷却时间；邮件失败最多尝试 3 次，反馈记录始终保留在后台。配置 `PUBLIC_SITE_URL` 后邮件包含反馈管理的网页链接，无需新增环境变量。

后台“反馈管理”提供“待处理 / 已处理”分页列表，每页 15 条。点击“审批”将未读标记为已读并移入已处理列表，单纯查看不改变状态。反馈图片保存于 `server/data/feedback/images`，仅管理员可通过受保护的 API 查看，不会公开到 `/picture` 或被资源上传清理程序删除。

`server/test/feedback.test.js` 用模拟邮件验证反馈权限、单选字段、图片校验与私有读取、滚动限流、审批状态、通知重试和邮件内容，不发送真实邮件。

## AI 学习

在项目根目录 `.env` 设置 `DEEPSEEK_API_KEY`，重启后端（Docker 部署需要重新创建 backend 服务）。在 `/admin` 的 **AI 学习** 页选择一个公开的合集，上传 PDF、PNG/JPEG/GIF/WebP、TXT/Markdown 文件，或填写网址、学习要求；三种输入可以任意组合。最多 12 个文件，每个不超过 50 MB。

- 模型固定为 `deepseek-flash`，密钥只由后端环境提供，Admin 不展示或修改。Harness 和 SDK 固定为 `0.2.0-rc.2`，直接安装 npm 发布包，构建不拉取浮动 master。
- 学习 Agent 可读取目标合集、全部子合集、文档、图集和草稿，先得到目录，再按需读取。PDF 提供分页文本和页面图片工具；图片直接作为多模态输入交给模型。公网 PDF 链接可以通过 `import_asset` 下载后读取。
- PDF 文本读取和图片渲染均在独立进程内执行，单次限时 60 秒，可随任务取消。底层渲染库异常退出会返回工具错误，Agent 可继续使用文本或跳过该页，HTTP 后端不会随之退出。
- Harness 提供原生搜索与网页获取。搜索走 DeepSeek 的独立 Messages 搜索接口，额外产生模型请求；压缩也会单独产生消耗。Admin 展示的 token 用量是主模型请求用量（含缓存输入），不包含搜索和压缩。
- 报告默认至少包含详细讲解和内容总结；例题取决于资料。可在学习设置中添加报告要求和任务时限，模型与密钥保持固定。项目不再设置主模型、搜索和压缩请求的输出 token 上限，沿用 Harness 与模型接口的原生设置；旧输出上限配置自动移除。
- 初始 64 次主模型迭代，每次调用 `extend_budget` 增加 64 次，最多 320 次。预算最后一次请求会收到提交或扩展预算提示。普通“完成”回复会继续循环；只有 `submit_document` 校验通过才公开发布，成功后停止模型调用。升级时尚未开始的旧排队任务会提升到 64 次；历史已结束记录保留原预算。
- 连续 3 次完整迭代没有任何文本、思考或其他内容输出，也没有工具调用时，在下一次请求注入提交任务提醒；有输出或工具调用则重新计数。提醒要求先保存当前任务报告再提交，不会由程序强制发布未完成草稿，原有预算和时限仍然有效。
- 后台串行执行任务，离开页面不会停止。Admin 可查看日志、已保存草稿、取消、重试和下载 Markdown。服务器重启后，运行中的任务记为失败，保留资料与草稿供重试，队列中的任务继续执行。
- 同一目标合集使用一个持久 Harness 会话，新任务和重试跨进程接续历史消息、工具结果、图片附件与压缩后的上下文；不同目标合集互相隔离。每个新任务、重试独立重置为 64 次预算，提交仍只作用于当前任务。恢复时清除上一任务未执行的继续指令，已提交的对话记录保留。升级时自动采用该合集最后一个仍保留在磁盘上的旧会话。共享会话独立存储在 `server/data/ai/collections/<合集ID>/harness`，删除单个任务记录不会删除它。
- 同一合集同时共用持久工作区 `server/data/ai/collections/<合集ID>/workspace`，删除单个任务不会删除工作区。模型使用 dsh 原生 `read/write/edit/read_image/glob/grep` 编写、检查和逐段修改 Markdown；保留原生工具的提示词与读后编辑规则，学习职责作为附加指令。默认报告为 `reports/<任务ID>.md`，也可在提交时指定工作区内其他 Markdown 路径及标题、摘要、标签、按钮。`submit_document` 读取文件后校验并发布，普通文本输出不自动发布。默认报告每次写入或编辑后同步数据库草稿快照。旧任务的辅助文件首次迁入 `workspace/legacy/<任务ID>/`；旧会话通过原生持久化接口保留完整历史，接续到以共享工作区为 cwd 的会话。
- 管理端日志展示模型文本和接口实际返回的思考片段（流式分批同步）、请求/迭代阶段、完整工具参数及结果、错误与压缩详情；可展开查看详细数据并分页加载早期日志。不会编造模型未返回的思考，密钥、图片二进制和思考签名隐藏，长文本按段保存。历史任务已经遗漏的输出无法补回。
- 上传和后续下载的 PDF 会由程序自动在报告顶部添加“学习源资料”链接。运行中、失败和已取消任务会保护附件；成功后转由帖子中的引用保护。删除任务记录会释放其附件引用，但保留已经生成的资源帖子；没有其他引用的附件会按原规则清理。
- 超时、预算耗尽或运行异常会生成 `server/data/ai/<任务ID>/error.md`，并在目标合集保存一篇**草稿**异常记录；成功的学习报告直接公开。任务目录不存在时，Admin 仍可从数据库下载保存的报告。

每个任务启动独立 Harness 子进程，使用合集共享工作区、合集持久会话目录和原生文件工具；文件工具读写和搜索限定在本合集工作区，校验真实路径以阻止符号链接越界。Agent 无通用 Shell 或数据库修改工具。网站资源读取权限由后台按目标合集校验，提交目的地固定；公网文件导入逐跳校验并固定 DNS 地址。额外的会话日志上传和遥测关闭，本地运行记录保存在 `server/data/ai`。Docker 后端使用 Node 24 Debian 镜像，并安装中文字体供 PDF 页面渲染。
